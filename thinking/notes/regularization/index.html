On Regularization, Simpler Perspective

When I was reading "Hands-On Machine Learning with Scikit-Learn and PyTorch by Aurélien Geron, 2026", I came across a paragraph on regularization in chapter 1 and i wanted to code them up and explain more in my point of view.

Paragraph : From Chapter 1

Constraining a model to make it simpler and reduce the risk of overfitting is called regularization.

For example, the linear model has two parameters, θ0 and θ1.

This gives the learning algorithm two degrees of freedom to adapt the model to the training data: it can tweak both the height (θ0) and the slope (θ1) of the line.

If we forced θ1 = 0, the algorithm would have only one degree of freedom and would have a much harder time fitting the data properly: all it could do is move the line up or down to get as close as possible to the training instances, so it would end up around the mean.

A very simple model indeed! If we allow the algorithm to modify θ1 but we force it to keep it small, then the learning algorithm will effectively have somewhere in between one and two degrees of freedom.

It will produce a model that’s simpler than one with two degrees of freedom, but more complex than one with just one.

You want to find the right balance between fitting the training data perfectly and keeping the model simple enough to ensure that it will generalize well.

That data, where x takes all values in range 0 to 200 and y is random values but are in a linear relationship with x values

This data can be fit perfectly with a Line, with some straight-line equation : y = θ1 * x + θ0.

Fitting a straight (non-bent or curved) line means to find a line passing through in same direction as data and as close as possible to all the data.

Mathematically, Fitting a Line means find the linear relationship of y with respect to x by finding best value of θ1 and θ0 in y = θ1 * x + θ0

def line(θ_0, θ_1, x):
  return θ_1 * x + θ_0

How do we tell a computer what is a good or bad line fit?

Once a Line is drawn, We can measure distance from each data point to the line. Then average this distance over the number of data points. Then do the same for other lines, find the average distance, and so on... for every possible Line.

Once we have all possible lines and their average distance with respect to data. The best fit line is a line with minimum average distance among all those lines.

This average distance is called MSE (Mean Squared Error)

In [9]:
def MSE(θ_0, θ_1, x, y):
  error = y - line(θ_0, θ_1, x)
  squared_error = error ** 2 # Distance
  return np.mean(squared_error)
In [10]:
def fit_and_measure(θ_0, θ_1, x, y):
  plt.scatter(x, y)
  for c, m in zip(θ_0, θ_1):
    line_fit = line(c, m, x)
    plt.plot(x, line_fit, label=f"MSE : {MSE(c, m, x, y)}")
  plt.legend()
  plt.show()

Here is a sample of lines and their measured average distance among them.

From this, if you look at the line and their MSE (Indicated by color).

The worse the line fit, the larger the MSE Value.

The better the line fit, the smaller the MSE Value.

The Best possible line is one with minimum MSE Value among all possible lines that can be fitted to this data

We can search for this line by checking every line's MSE

In [12]:
def find_best_line(x, y):
  best_mse = float("inf")
  best_θ_0 = None
  best_θ_1 = None
  for m in range(-100, 1000):
    for c in range(-100, 1000):
      θ_0 = c/10
      θ_1 = m/10
      mse = MSE(θ_0, θ_1, x, y)
      if mse < best_mse:
        best_mse = mse
        best_θ_0 = θ_0
        best_θ_1 = θ_1
  return int(best_mse), best_θ_0, best_θ_1

Any model, Which said to be good model should be better than Baseline Model

From Paragraph :

A very simple model indeed! If we allow the algorithm to modify θ1 but we force it to keep it small, then the learning algorithm will effectively have somewhere in between one and two degrees of freedom.

Forcing θ1 to be small is regularization. And there are 2 ways to do this.

L1 & L2 regularization

How do we make sure θ1 is Small Enough? The same way we make sure MSE is Small Enough

In [16]:
def MSE_with_L1_regularization(θ_0, θ_1, x, y, Lambda_=793):
  error = y - line(θ_0, θ_1, x)
  squared_error = error ** 2 # Distance
  return np.mean(squared_error) + Lambda_*abs(θ_1)
In [17]:
def MSE_with_L2_regularization(θ_0, θ_1, x, y, Lambda_=793):
  error = y - line(θ_0, θ_1, x)
  squared_error = error ** 2 # Distance
  return np.mean(squared_error) + Lambda_ * θ_1**2

Now if we fit the line, we will see it's not the best fit, but good enough fit.

In [18]:

We used L1 Regularization, which simply tried to suppress the magnitude of θ_1

Here we see that θ_1 is 0.9, not 1. So L1 regularization worked well. This line is slightly not perfect, as expected.

The goal of regularization is to try to make line not to fit perfectly. We want the line to be fit well enough

The Lambda_ in MSE_with_L1_regularization controls How much θ_1 wants to be reduced.

Also, if we focus more on reducing θ_1 (by making Lambda_ very high like 1000+) we will lose fit as MSE will not be good.

On the Other Hand, if we don't focus on reducing θ_1 (by making Lambda_ very low like even 0). all we do is the best fit with minimum MSE.

So if Lambda_ = 0, We Focus on MSE , No Focus on θ_1 and if Lambda_ is Very high. We don't focus on MSE, We Focus on θ_1

If Lambda_ is between 0 and High, like 500. We equally Focus on MSE and θ_1

As Lambda_ increases, θ_1 reduces.

If Lambda_ is very high, we get θ_1 = 0, the baseline model.

This applies the same way for L2 regularization.

The difference is not seen when there is only one parameter θ_1.

In different models, we can have θ_1, θ_2, ..... where the L1 and L2 difference is seen

Note: We never regularize θ_0 (known as the intercept here, and also known as the bias in other models)
