AlexNet.

Reproducing a landmark convolutional neural network from the 2012 ImageNet paper, then training it locally to understand the architecture, training recipe, compute requirements, and the gap between a paper result and a real reproduction.

2012 paperCNNImageNetPyTorch / KerasRTX 5050ReLU / LRN
01 / The project

Not just an implementation. A reproduction.

The goal was to reproduce AlexNet as described in the original paper: its architecture, layers and training setup, then run the complete pipeline locally — from dataset loading and augmentation through training, evaluation and visualization.

The interesting part was the scale. The training set was roughly 1.2 million images across 1,000 classes. The dataset occupied about 150 GB, while the implementation contained 62,378,350 trainable parameters.

What I actually did

Built the network, prepared the ImageNet pipeline, tuned the CPU-side dataloader so the GPU could stay supplied, trained for 90 epochs, reproduced two of the paper's smaller ablations, evaluated the model, and inspected what the network learned.

02 / Architecture

Five convolutional layers. Three fully connected layers.

AlexNet is an eight-layer learned network: five convolutional layers followed by three fully connected layers and a 1000-way softmax. The stored training images are 256×256 and are cropped to 224×224 patches for training.

01

Spatial shrinking

224×224 → 55×55 → 27×27 → 13×13 → 6×6. Pooling progressively compresses spatial information while the convolutional stack builds richer representations.

02

Feature depth

96 → 256 → 384 → 384 → 256 feature maps. The network trades spatial resolution for increasing feature depth.

03

Regularization

LRN follows Conv1 and Conv2; overlapping 3×3 pooling follows those normalized layers and Conv5; dropout is used in the first two fully connected layers.

04

Paper → reproduction

The original paper distributed convolutional work across two GPUs. This reproduction ran on a single RTX 5050.

03 / Training

The bottleneck wasn't only the model.

A major part of the experiment was getting the data pipeline to keep the GPU supplied with data. Augmentation was performed on the CPU, so the dataloader had to be optimized to avoid leaving the GPU waiting.

04 / Ablation studies

Reproducing the paper's smaller experiments.

The original AlexNet paper tested individual architectural choices rather than presenting only the final network. I reproduced two of those comparisons on a smaller four-layer CNN using CIFAR-10.

ReLU vs Tanh

  • The activation function is the isolated variable.
  • Both versions use the same four-layer CNN.
  • The reproduction used Adam with early stopping at the recorded accuracy threshold.
  • The paper found ReLU networks reached 25% training error substantially faster than equivalent Tanh networks.

LRN vs No LRN

  • The normalization mechanism is isolated.
  • The same four-layer CNN is compared with and without Local Response Normalization.
  • The reproduction trained the two versions for 10 epochs with validation data.
  • The paper reports 13% test error without normalization and 11% with normalization on its CIFAR-10 comparison.

06 / Reproduction gap

The numbers didn't match. That's part of the experiment.

The original paper reported 37.5% Top-1 error and 17.0% Top-5 error on its test data — approximately 62.5% Top-1 and 83% Top-5 accuracy. The implementation did not reach those numbers on the available validation evaluation.

Original paper

  • ~62.5% Top-1 accuracy
  • ~83% Top-5 accuracy
  • Test-data evaluation
  • Multi-GPU setup

This reproduction

  • 52.86% validation Top-1 accuracy
  • 75.73% recorded validation Top-5 metric
  • Validation evaluation
  • Single RTX 5050
01

PCA color jitter

The implementation used the simpler transformations described in the paper but did not implement PCA color jittering.

02

Multi-GPU training

The original setup used multiple GPUs and cross-GPU connections; the implementation was trained on a single RTX 5050.

03

Learning-rate schedule

An earlier learning-rate reduction was identified as another possible contributor to the difference.

04

No labeled test set

The available test labels were not available, so evaluation was performed on the validation set. No hyperparameter tuning was performed.

09 / Takeaway

A model is more than its architecture.

The implementation made the practical side of a classic deep-learning experiment visible: the dataset pipeline, preprocessing, compute, training schedule, evaluation choices and the small implementation details that can separate a reproduction from the original result.

AlexNet was published in 2012. Rebuilding it locally made me appreciate how much of deep learning is everything around the model itself.
